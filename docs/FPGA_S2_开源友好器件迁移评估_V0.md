## 1. 为何需要 S2

| 已具备（S0/S1） | 仍缺 |
|-----------------|------|
| RTL 可 Verilator 仿真 | **xc7z020 全开源 bitstream** 短期不可行 |
| Yosys generic 综合对照 | nextpnr/开源后端对 Zynq-7000 PL **无产品级闭环** |
| Vivado 钉版本 batch 出 bit（辅） | 硬主权 = 逻辑→仿真→**实现→bit** 全链不绑 AMD |

现板 **PYNQ-Z2（xc7z020）** 继续作：Atlas 协同、双通证据、Vivado 辅证平台。  
S2 回答：**若要把「出 bit」也迁出 Vivado，候选是什么、代价是什么。**

## 2. 候选对照（研究轨）

| 候选 | 开源综合→bit | 资源量级 vs 现 LIF | 与 Atlas/现网 | 备注 |
|------|----------------|-------------------|---------------|------|
| **维持 Z2 + Vivado 辅** | ❌ bit 仍闭源 | 已验证（~379 LUT LIF） | ✅ 现网双通 | **默认过渡**；S0/S1 已覆盖信任根 |
| Lattice **ECP5**（如 Versa / Colorlight） | ✅ Yosys+nextpnr-ecp5 成熟 | 中大；够单核/小阵列 | 须重做板级与 PS 侧 | 开源社区最常用「可控实现」档 |
| Lattice **iCE40** | ✅ 极成熟 | 偏小；整网分时也紧 | 弱 | 仅适合极简 PoC，不推荐主推理 |
| Gowin（Tang 等）+ 开源探索 | ⚠ 工具链参差 | 中 | 弱 | 可跟踪，不作首选 |
| 国产/可控 SoC+FPGA 模组 | 视厂商 SDK | 视选型 | 须单独立项 | 产品级选项；本评估不点名采购 |

**并行整网（256 LIF）**在 Z2 已撞 LUT 墙；迁 ECP5 **不自动**解决「要并行还是分时」——资源与架构仍要单独算。

## 3. 建议（研究轨默认）

1. **主推理/加速路径**：维持 **Atlas +（可选）Z2 PL 加速/分时整网**；信任根继续 **Verilator + RTL-CR**；bit 辅证 Vivado 2023.2。  
2. **S2 PoC 触发条件**（须总裁书面）：安全可控升为**硬约束**且验收要求「无 Vivado 可复现 bit」。  
3. **一旦触发**：首选 **ECP5 + Yosys/nextpnr** 做 `lif_step` 同构移植 PoC（仿真门复用；板上 gate 新建）；Z2 降为对照平台写入架构真源。  
4. **不触发**：不采购、不改 `NEURO-V1` 主器件绑定；本文件保持评估结论。
