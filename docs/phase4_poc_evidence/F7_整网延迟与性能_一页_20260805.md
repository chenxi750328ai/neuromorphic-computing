## 2. 延迟数字（诚实）

| 指标 | 数值 | 说明 |
|------|------|------|
| 墙钟合计 | **≈6124 s（≈102 min）** / 20 张 | `board.wall_ms` |
| **单张墙钟** | **≈306 s/张** | 不可当产品推理延迟 |
| fc 在 PL 累计 | ≈6047 s（**≈98.7%**） | `fc_pl_ms` · 绝对主导 |
| LIF 在 PL 累计 | ≈77 s（≈1.3%） | `lif_pl_ms` |
| MAC/LIF 调用 | 各 **133000** 次（≈6650/张） | time-mux 细粒度踢 IP |

**对照（同项目 Atlas 推理尺子，非同切分）**：daemon G-LAT r2 **p50≈3.5 ms**（N=100 vs ORT）。  
→ **F7 当前实现是「功能上板」级，不是「加速比」级**；与 Atlas 毫秒级不在同一优化面。

---

## 3. 为何这么慢（根因，非板子装不下）

1. **Time-mux + MMIO**：每步由 PS 写寄存器触发 MAC/LIF，事务开销 ≫ 算子本身。  
2. **调用次数爆炸**：25 tick × 多层 fc 展开成 6.6k 次/张级 PL 踢门。  
3. **未做**：权值/激活 DMA 流、批处理、PL 内调度器、时钟域流水。  
4. **F7 选项 3 验收**：只要求 pred≡golden；**未立延迟门禁**——故合入时没有单独「性能报告」页（缺口在本页补）。

## 4. 若要性能下一刀（建议，另开 WO）

| 优先级 | 方向 | 预期 |
|--------|------|------|
| P0 | 减少 MMIO 往返：tick/层级 batch kick 或 AXI-stream DMA | 数量级下降墙钟 |
| P1 | PL 内 micro-scheduler（少 PS 介入） | 降编排占比 |
| P2 | 与 Atlas 同 bench 协议出 p50 表 | 才有资格谈「加速」 |

**未达标前禁止对外说「FPGA 整网已加速」。** 可说：「整网 PL 功能通，延迟未优化。」
