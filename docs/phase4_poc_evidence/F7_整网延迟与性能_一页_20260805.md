## 2. 延迟数字（诚实 · 2026-08-05 Phase4.2 exec）

| 指标 | 数值 | 说明 |
|------|------|------|
| 墙钟合计 | **≈6124 s（≈102 min）** / 20 张 | Phase4.1 板测 `board.wall_ms` |
| **单张墙钟** | **≈306201 ms/张（≈306 s）** | **P4.2-LAT 未达标**（阈值 100 ms） |
| fc 在 PL 累计 | ≈6047 s（**≈98.7%**） | MMIO 细粒度 kick 主导 |
| LIF 在 PL 累计 | ≈77 s（≈1.3%） | |
| MAC/LIF 调用 | 各 **133000** 次（≈6650/张） | time-mux |

**Phase4.2 本轮**：软件 fast-MMIO + 紧轮询（同 overlay）；**板不可达未复测**——延迟仍引用 4.1 基线。  
**禁止宣称加速**；可说：「功能通，性能攻关中，STALL 未解。」

---

## 3. 为何这么慢（根因）

1. **Time-mux + MMIO**：每步 PS 写寄存器触发 MAC/LIF，AXI 事务 ≫ 算子。  
2. **6650 次/张** PL kick — 需 PL 内 tick 调度器（`fullnet_tick_scheduler.v` 草案已落盘）。  
3. **未做**：权值 DMA 流、批 kick、overlay v2 比特流。  
4. 软件轮询优化 **不能** 数量级降延迟。
