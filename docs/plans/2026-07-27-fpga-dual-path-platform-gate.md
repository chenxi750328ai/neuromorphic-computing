## 1. 要证明什么（人话）

| 路线 | 要证明的「平台可用」 | 现在到哪了 |
|------|----------------------|------------|
| **R-A · FPGA 做加速** | 整网主推理仍在 Atlas（或 4090），FPGA 只承担**切分出去的一块**（如前处理 / 单层 LIF），入链后仍能对上金标准，并留下延迟/资源账 | 仅有 **单步 LIF 上 PL**（工具链通）；**未做「Atlas+FPGA 入链」对照** |
| **R-B · FPGA 跑整网** | MNIST SNN **整网定点推理在 FPGA/PL 上跑通**（分类结果可对照），并留下延迟/资源账 | **未做**（定点全网目前主要在 WSL 软件定点，未整网烧板） |

**对照锚点（已有、不重复造）**：Atlas **整网** OM 推理 + daemon 延迟尺子已过 → 作为「边缘 AI 芯片路径」基线。

---

## 2. 「平台可用」最低验收（两条路各自一张表）

共同口径（与探索规格精神一致，数字可微调但须先写死再测）：

| 项 | 最低要求 |
|----|----------|
| **功能** | 与金标准（ORT 或 Atlas）预测一致率达暂定线（建议沿用 G-ACC ≥98% 或 pred 全一致探针，测前钉死） |
| **延迟** | 填端到端或「切分段」延迟；**允许先不达 G-LAT 5ms**，但必须有数；若破尺须写清「破在哪一段」 |
| **资源** | LUT/BRAM/DSP（或等价）报告落盘 |
| **工具链** | 可复现：源码/RTL → 综合 → bit → 板上跑 → JSON 证据 |
| **结论资格** | 只宣称「该路线平台可用/不可用」；**不**自动定最终产品 BOM |

**R-A 额外**：至少 **1 种真实入链切分**（建议优先 **M-lif**：FPGA=LIF 层，Atlas=其余；或 M-pre），与「仅 Atlas」同行填 [探索规格 §4](../Phase4.1_探索规格与补数议程_V0.md)。  
**R-B 额外**：整网在 PL（或「PL 算子链覆盖整网前向」）上跑通分类；若 PYNQ-Z2 资源不够，允许结论为 **「本板不可用、需更大 FPGA」**——这也算「平台验证有结论」，不是空白。

---

## 3. 为何必须双验（防白搞）

```text
若只验加速、后来要整网 → 可能板资源/工具链不够 → 长线白做
若只验整网、后来要加速 → 可能入链通信/切分不可用 → 长线白做
方案未钉死 → 两条都验「通/不通/在什么条件下通」→ 再选长线
```

Phase8（STDP 等）**排在本闸门之后**（或总裁书面授权并行，默认不并行）。
