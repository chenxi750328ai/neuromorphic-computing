## 2. 现网 CI/CD 盘点

### 2.1 已有（相对完备）

| 层 | 现状 |
|----|------|
| Workflow | `.github/workflows/ci.yml` · job `qa` · `neuro-ci` |
| Runner 门禁 | `qa-neuro-baseline-run.py --tier ci`（syntax/smoke/shell/docs/verilator/yosys/s2/both-evidence/vivado-bit 等，见 `config/neuro-qa-gate-baseline.json`） |

### 2.2 缺口（不完备 · 本次事故直接相关）

| ID | 缺口 | 影响 |
|----|------|------|
| **G1** | GitHub **无 required reviews**（`required_pull_request_reviews=null`） | 有写权限即可在 qa 绿后 merge |
| **G2** | CI **不读** vcompany `WO-TEST-*` / `awaiting_acceptance` | neuro-ci 过 ≠ IPD 测试过 |
| **G3** | Agent/`gh pr merge` **无本地 IPD pre-merge 门禁**（此前） | 唤醒条「审合」可直接合掉 |
| **G4** | 板上/硬件证据 **无法**进 GitHub runner | 必须靠 WO-TEST + 证据 JSON；CI 只能做 RTL/仿真/文档层 |
| **G5** | `pre_merge` tier 存在于 baseline，**未**挂到 workflow / 未做 required check | 合入前加强门禁未强制 |

## 3. 正确合入链（IPD）

```
DEV WO EXEC PASS → TEST WO EXEC PASS（沟通/验收）
  → 开/重开 PR → neuro-ci qa 绿
  → 人审（建议开 required review）
  → merge → VP 关单
```

**禁止**：仅 neuro-ci 绿就合；TEST 后补 PASS 洗白顺序。
